# ChopChop

Мультяшное воксельное расчленение для Minecraft Java **26.2 / 26.3** (Fabric). Удары вырывают из тела маленькие
кусочки, под кожей видно мясо, мечи и топоры отсекают конечности, из обрубков торчат смешные кости, отрубленное
падает на землю. Раны решает сервер, все клиенты рядом видят одно и то же.

По умолчанию режим **только визуальный**: геймплей не меняется.

## Варианты запуска

| Сервер                         | Клиент              | Что нужно                                                      |
|--------------------------------|---------------------|----------------------------------------------------------------|
| Fabric (выделенный)            | Fabric + ChopChop   | `chopchop-<версия>.jar` в `mods` сервера и клиентов            |
| Paper                          | Fabric + ChopChop   | `chopchop-paper-<версия>.jar` в `plugins` сервера              |
| Одиночная игра / LAN           | Fabric + ChopChop   | только мод: встроенный сервер работает как Fabric-сервер       |

Fabric-сервер и Paper-плагин — два бэкенда одного протокола. Правила ран, профили тел и протокол — общий код
`src/shared`, он компилируется и в мод, и в плагин.

Клиенты без мода на таком сервере играют как обычно и ничего не видят. Клиент с модом на сервере без ChopChop
ничего не рисует.

Сборка: `gradlew buildAll` → `build/libs/` (мод для 26.2 и 26.3 и плагин).
Проверки: `gradlew test` (ядро), `gradlew runClientGameTest` (игра целиком, скриншоты в
`build/run/clientGameTest/screenshots`).
Против живого Paper: запустить Paper с плагином так, чтобы консоль читалась из файла
(`tail -f cmd.txt | java -jar paper.jar nogui`), затем
`gradlew runClientGameTest -PpaperPort=<порт> -PpaperConsole=<путь к cmd.txt>` — клиент подключается, удары
наносятся `/damage ... by @p`, проверяются раны зомби, отсечение и раны игрока.

## Зависимости

| | обязательно | опционально |
|---|---|---|
| Fabric Loader, Fabric API | ✔ | |
| Cloth Config (+ Mod Menu) | | экран настроек; без него — файл `config/chopchop-client.json` |
| ModelInteractions | | совместим: раны следуют за частями, которые он тянет; отрубленное целиком (голову, руку от плеча) схватить нельзя |

что и клиенты.

## Как это устроено

### Сервер решает, клиент рисует

1. Сервер видит урон, который игра **реально нанесла**: Fabric — миксин на `LivingEntity.hurtServer`
   (вернул `true` и здоровье/поглощение уменьшилось после брони); Paper — `EntityDamageEvent` на `MONITOR` без
   отменённых, а применение — на следующем тике, если цель действительно потеряла здоровье. Щит, неуязвимость,
   отмена другим плагином, броня «в ноль» — ран нет.
2. Точка попадания ищется на позе покоя профиля (см. ниже), правила (`WoundEngine`) вырезают воксели и, может
   быть, отсекают сегмент.
3. Всем, кто видит сущность (и ей самой, если это игрок), уходит `S_EVENT` (частицы и звук) и `S_STATE` (всё
   состояние сущности целиком). Состояние заменяет прежнее, поэтому рассинхрон не копится.
4. Начало слежения (`EntityTrackingEvents` / `PlayerTrackEntityEvent`), вход, смена мира, респавн — состояние
   переотправляется. Как в VRCamera: один plugin channel `chopchop:sync`, байты без обёртки, `C_HELLO` с версией.

### Профили тел (`src/shared/resources/chopchop/profiles`)

Данные, а не код: части (имя части модели, родитель, pivot и поворот покоя, бокс, сетка вокселей), оверлеи
(рукава, куртка, шапка), рука (`hand`), сегменты отсечения (`cut` — строка вокселей, `durability`), материал
(`meat` / `bone`), размер кости в обрубке. Встроены: `player`, `zombie` (руки вытянуты вперёд, как рисует игра),
`humanoid` (пиглины), `skeleton` (кость внутри, без крови), `pig` (четвероногий, повёрнутое тело).

Сущность без профиля не получает ран вовсе — никакого «универсального гуманоида». Сервер может переназначить или
выключить тип: `entityProfiles` в `config/chopchop-server.json` / `entity-profiles` в `config.yml`.

### Рендер: кожа действительно исчезает

Миксин на `ModelPart.Cube.compile`: куб повреждённой части рисуется заново — каждая грань нарезается по клетке на
тексель, клетка над пропавшим вокселем **не рисуется**. Стенки и дно раны — грани мяса между целыми и
пропавшими вокселями, срез обрубка получается так же. Всё в пространстве части, поэтому раны едут вместе с
анимацией (ходьба, удар, плавание, присед). Мясо и кости — свои текстуры, они собираются и пишутся в свои буферы
в том же проходе `ModelFeatureRenderer`.

| Что | Как |
|---|---|
| Оверлеи (рукава, куртка, шапка, внешний слой утопленника) | те же дыры, без мяса |
| Броня | исчезает только отрубленное, порез кожи броню не дырявит |
| Предмет в отрубленной руке | не рисуется (3-е лицо — `ItemInHandLayer`, 1-е — рука целиком) |
| Тонкие руки (slim) | сетка накладывается на свой куб части, нормированно |
| Детёныши, `scale` | нормированно на куб; сервер учитывает `getScale()` |
| Невидимые | тела нет — ран нет; полупрозрачные (зритель) — дыры без мяса |
| Свечение (контур) | контур с дырами, мясо в контур не идёт |
| Руки от 1-го лица | раны и мясо видны; отрубленная рука не рисуется |
| Отрубленное | копия сегмента на момент удара (кожа, прежние раны, срез, кость), падает и исчезает через N секунд, только у клиента |

**Не поддерживается:** Customizable Player Models, Figura и любые свои рендеры, которые не рисуют ванильные
`ModelPart`: у таких моделей ран не видно (сервер их всё равно считает). Модели модов без профиля — без ран.

### Где попал удар (главная инженерная проблема)

Ни пакет атаки, ни событие урона не содержат точки на анимированной руке — сервер анимацию не знает вообще.

- **Стрелы, трезубцы:** луч по траектории снаряда (позиция и скорость в момент удара), через сетку вокселей.
- **Ближний бой:** луч из глаз атакующего по взгляду (игрок) или к центру цели (моб), на дистанцию досягаемости;
  если луч прошёл мимо модели (удар по хитбоксу) — берётся ближайшая к лучу часть.
- **Остальное** (взрывы, падение, огонь): `otherSources: skip` (по умолчанию) или `coarse` — луч от источника, при
  падении — в ноги.

Точка ищется на позе покоя профиля, повёрнутой как сущность (`yBodyRot`, масштаб, наклон при плавании и полёте на
элитрах). Это приближение: размах руки в анимации сервер не видит. Луч идёт по вокселям и останавливается на
первом целом, поэтому повторный удар в то же место углубляет рану, а удар по уже отрубленному сегменту его не
находит и второй раз не отрубает.

**Попадание по модели.** На сервере с ChopChop прицел клиента находит тело и по модели, а не только по хитбоксу:
вытянутые руки зомби торчат из его коробки, и теперь по ним можно попасть. Проверка — сразу после ванильного
выбора цели, только если он не нашёл сущность, и только для тел в пределах досягаемости (дёшево). Удар идёт
обычным пакетом: сервер принимает его, пока хитбокс цели в пределах досягаемости с ванильным запасом, а руку находит
тем же лучом по позе покоя.

### Отсечение

Сегменты задаются строкой вокселей: удар ниже середины руки — по сегменту `lower` (отпадает кисть с предплечьем),
выше — по `upper` (отпадает почти вся рука). Отрубленное = всё ниже строки разреза, поэтому вместе с верхним
сегментом уходят и нижние. Сегмент копит урон × множитель оружия; когда накопилось `durability`, срабатывает с
шансом `severChance` и только для одиночного удара сильнее `minSeverDamage` — не на каждом ударе. Отрубают
только мечи и топоры (по умолчанию), голова — никогда (`heads: false`).

**Сила удара.** Сегмент копит урон × множитель оружия × `1 + (урон − minSeverDamage) × severHeavyBonus`, а шанс
отсечения растёт на `severChancePerDamage` за каждую единицу урона выше `minSeverDamage` (до 0.95).

**Добивающий удар.** Зомби умирает с 3–4 ударов, раньше, чем конечность «износится». Поэтому удар мечом или топором,
который убил, отрубает то, куда попал, с шансом `lethalSeverChance` (0.6) независимо от прочности, голову — с шансом
`lethalHeadChance` (0.45). Урон добивающего удара берётся полный, а не остаток здоровья. Тяжёлый удар по голове
считается за `1 + урон / headHitDamage` ударов (8): топор с 9 урона — за два.

### Голова и ноги

- **Голова** отлетает с трёх рубящих ударов (меч/топор) именно по голове — счётчик ударов в профиле (`hits: 3`),
  без шанса и порога урона. Мобы смотрят туда, куда бьют, поэтому зомби с мечом рубит в голову, когда смотрит в глаза.
- Без головы **игрок** стоит ещё `headlessPlayerSeconds` (2 с) без управления и падает замертво, **моб** бегает
  вслепую `headlessSeconds` (3 с) и умирает. Убийство засчитывается тому, кто отрубил.
- **Камера в голове**: у игрока, которому отрубили голову, камера летит в ней, голова кувыркается, подпрыгивает с
  «чпоком», ложится ровно и поворачивается лицом к своему телу. Экран смерти ждёт `headCamSeconds` (5 с).
  Голова в мире видна всем, из шеи бьёт фонтанчик крови, на теле — мясной обрубок с костью.
- **Kill-cam** у того, кто отрубил голову: на `killCamSeconds` (2.5 с) камера плавно выходит из глаз, облетает
  летящую голову (тело и сам игрок в кадре), не проходит сквозь стены и возвращается. Управление не отнимается,
  двигается только камера. Сервер присылает id атакующего в событии отсечения.
  Если рядом (`killCamThreatRadius`, 8 блоков) есть монстры, нацеленные на игрока: `killCamThreats: skip` — kill-cam
  не включается (по умолчанию), `freeze` — они замирают на время камеры (Fabric: AI выключается и возвращается,
  Paper: `setAware(false)`), `ignore` — включается всё равно.
- **Порезы**: меч и топор режут полосу-шрам поперёк замаха (длина растёт с уроном), тупое и стрелы — круглые
  выемки, теперь крупнее.
- **Глубина и сторона**: топор рубит на `axeExtraDepth` (1) вокселя глубже меча. Рана углубляется только со стороны
  удара и никогда не выходит на противоположную грань части: удар в грудь не открывает спину. Раньше части толщиной
  4 вокселя пробивались насквозь повторными ударами — отсюда «бью спереди, а дыра на спине».
- **Разоружение** (`disarmMobs`): моб, потерявший руку с предметом, теряет предмет (`disarmDrops` — выпадает на землю,
  иначе исчезает, чтобы не фармить снаряжение). Скелет без руки с луком не стреляет и не поднимает лук обратно; моб без
  обеих рук не атакует. Fabric: миксин на `doHurtTarget`/`wantsToPickUp`; Paper: отмена `EntityDamageByEntityEvent`,
  `EntityShootBowEvent`, `EntityPickupItemEvent`. Игроков не касается.
- **Трупы** (`corpseSeconds`, 20 с): умерший моб с профилем остаётся у клиентов с модом телом со всеми ранами —
  заваливается от последнего удара (направление и случайность приходят с сервера одним сообщением `S_CORPSE`, у всех
  клиентов одинаково), отскакивает, в конце уходит в землю. Сервер удаляет сущность как обычно, клиент держит её у
  себя: без дымка смерти, прицел и толчки проходят сквозь тело. Одинаково на Fabric и Paper.
- **Взрывы** вырывают куски крупнее и глубже удара: `explosionWoundDepth` (2), `explosionWoundScale` (1.6), до
  `explosionCarvedShare` (0.6) части.
- **Взрывы** (TNT, крипер, кровать): лучи от точки взрыва рвут сторону тела, обращённую к нему; выше
  `explosionSeverDamage` конечности со стороны взрыва отрываются и улетают от тела, чем ближе — тем вероятнее и
  тем больше отрывает; голову — только очень близкий взрыв.
  Игрок, погибший от взрыва, теряет голову всегда (`explosionDeathTakesHead`): она улетает прочь от точки взрыва со
  случайным отклонением, камера в ней, экран смерти ждёт (даже если пришёл раньше головы — взрыв убивает внутри урона).
- **Обе ноги** (`legless`): `crawl` — игрок ползёт ванильной позой (низкий хитбокс, анимация ползания, видна всем
  без мода); моб ложится на живот и (`leglessMobs: lie`, по умолчанию) лежит неподвижно с выключенным AI — не ходит,
  не атакует, только головой следит за ближайшим игроком (Fabric: шаг AI пропускается миксином, в NBT ничего не
  пишется; Paper: `setAware(false)`, возвращается при выгрузке, лечении и выключении плагина). `leglessMobs: crawl` —
  ползёт за целью медленнее (`crawlSpeed`). Лежачему голову сносит один удар (`leglessHeadHits`). Попадания
  считаются по лежащему телу;
  `protect` — последнюю ногу не отрубить; `none` — ничего не происходит.

### Восстановление

- Раны игрока сбрасываются при респавне после смерти. Пока игрок мёртв — тело остаётся израненным.
- Переподключение не лечит: сервер помнит раны по UUID, пока работает.
- `persistPlayers` — раны игроков переживают рестарт (Fabric: `<мир>/chopchop-wounds.json`, Paper: PDC игрока).
- Мобы: раны живут, пока моб загружен; выгрузка чанка или смена измерения — моб снова цел.
- Отрубленные куски — косметика клиента: лежат `debrisSeconds` (12) и плавно растворяются (прозрачность за 2 с).
  Игрок, наступивший на кусок, пинает его (`debrisKick`).

## API для других модов

Свой мод боя (замахи, парирование) может сам отрубать нужную конечность в нужном месте и оставлять раны нужной
формы: `ru.deelter.chopchop.api.ChopChopApi` (Fabric) и `ru.deelter.chopchop.paper.api.ChopChopApi` (Paper).
Подробно, по-английски — [API.md](API.md).

## Настройки

Сервер (`config/chopchop-server.json`, Paper — `plugins/ChopChop/config.yml`): шанс раны, радиус (база, на единицу
урона, максимум), глубина, доля вырезанного, шанс и прочность отсечения, минимальный урон для отсечения, множители
оружия (`sword`, `axe`, `trident`, `arrow`, `blunt`, `other`), `otherSources`, `persistPlayers`, профили для типов.

Клиент (`config/chopchop-client.json` или экран Cloth Config): рисовать ли раны, частицы и их количество, звуки и
громкость, падающие куски и их время, кости, раны на своих руках, прятать предметы, дальность.

Paper: `/chopchop reload | stats | heal [игрок]` (право `chopchop.admin`).

## Геймплейный режим (дизайн, не в MVP)

Сейчас всё визуально. Предлагаемый опциональный режим и его цена:

| Что | Как сделать | Цена |
|---|---|---|
| Нет руки — нельзя использовать предмет | серверная проверка в `ServerGamePacketListenerImpl` на use item / use item on / attack, по стороне: `mainArm` даёт правую/левую руку → main/offhand | средняя: много путей ввода, у каждого свой пакет |
| Предмет выпадает один раз | при отсечении сервер выкидывает **выбранный слот хотбара** или offhand через `Inventory.removeItem` + `drop`, флаг «уже выронено» в состоянии части, никогда на клиенте | средняя; дубликаты исключает только серверная операция с проверкой, что стек ещё там |
| Нельзя взять обратно | блок `setItemInHand`/pickup в слот отрубленной руки: смена слота хотбара, `F`-swap, клики в инвентаре (`AbstractContainerMenu.clicked` с SWAP/QUICK_MOVE/PICKUP), shift-клик, драг, пикап с земли | **высокая**: десяток путей, каждый — источник дюпа/рассинхрона |
| Копать offhand-ом | ваниль не копает offhand-ом: скорость, прочность, чары, cooldown атаки, анимация — всё от main hand. Нужно подменять «главную руку» на сервере и клиенте | **очень высокая**, ломает совместимость; не рекомендую |
| Ноги | замедление `MOVEMENT_SPEED` модификатором атрибута | низкая |

Рекомендация: если делать, то режим «без рук нельзя **атаковать и использовать** этой рукой» + одно выпадение
предмета при отсечении, без запретов на инвентарь и без копания offhand-ом. Смерть и респавн уже сбрасывают
состояние; на переподключении сервер отдаёт то же состояние, вещи не трогает.

## Известные ограничения

- Попадание в ближнем бою — по позе покоя профиля, а не по кадру анимации клиента.
- Свои отрубленные конечности от первого лица не видно падающими (тело игрока в 1-м лице не рисуется).
- Безголовый игрок 2 секунды не может ходить, но клик атаки/использования не заблокирован.
- Paper: старый `config.yml` с явным `heads: false` остаётся как есть — новые ключи берутся из значений по умолчанию.
- Предмет у глаза (подзорная труба) в отрубленной руке игрока рисуется — у `PlayerItemInHandLayer` свой путь.
- Произвольные разрезы под любым углом — будущая работа; сейчас только заранее заданные строки разреза по оси y.
